# Project status

## Stato corrente

Legacy-active / stable.

Il progetto non viene lasciato in sospeso tra due architetture:

- la pipeline reale resta notebook-driven
- il valore pubblico del progetto vive nelle Discussions e nei notebook di risposta
- il repo viene chiuso documentando bene questo stato

## Perimetro confermato

- `saldi storici`
- `spese per missione / programma / macroaggregato`

Fuori perimetro:

- nuova linea `entrate` come dataset separato
- migrazione completa al `toolkit` in questo repo

## Stato delle Discussions principali

| Discussion | Stato repo |
|---|---|
| Deficit strutturale | risposta pubblicata, notebook importato |
| Ricorso al mercato | commento pronto, notebook in attesa di push |
| Avanzo primario | materiale da riallineare nel repo |
| Entrate tributarie | materiale da riallineare nel repo, notebook in attesa di push |
| Spese correnti vs investimenti | commento pronto, notebook in attesa di push |
| Interessi sul debito | discussion pubblicata, output da collegare |

## Cosa manca per chiudere bene

1. importare nel repo i notebook già condivisi nelle Discussions
2. collegare ogni Discussion principale a un notebook o commento dati
3. lasciare esplicito cosa resta fuori dal progetto

## Follow-up possibile

Se in futuro nascerà una versione `toolkit-native`, dovrà essere trattata come filone separato e non come retrofit di questo repo legacy.
